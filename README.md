# octavia-dev

Container image for running [Octavia](https://opendev.org/openstack/octavia) (wallaby-eol) with the [OVN provider](https://opendev.org/openstack/ovn-octavia-provider) from local source checkouts, suitable for development against an existing devstack environment.

## Prerequisites

- podman
- openstack CLI with credentials for the target environment
- A running OpenStack (devstack) environment

## Build

Source your OpenStack credentials, generate `build.env` from the live environment, then build the image:

```sh
source /opt/stack/openrc admin admin
./generate-build-env.sh
./build.sh
```

`build.sh` will:
1. Clone `octavia` and `ovn-octavia-provider` at `wallaby-eol` if not already present
2. Generate `etc/octavia.conf` from `etc/octavia.conf.template` + `build.env`
3. Generate `octavia.yaml` from `octavia.yaml.template` with absolute paths
4. Build the `octavia:wallaby` image

## Configuration

`build.env` is generated by `generate-build-env.sh` and holds all environment-specific values:

| Variable | Description |
|---|---|
| `CONTROLLER_HOST` | IP of the OpenStack controller (derived from `OS_AUTH_URL`) |
| `HM_IP` | IP the health manager binds to (defaults to `CONTROLLER_HOST`, override via env if different) |
| `CAFILE` | Path to the CA bundle |
| `RABBIT_PASSWORD` | RabbitMQ password |
| `DB_PASSWORD` | MySQL password |
| `OCTAVIA_PASSWORD` | Octavia service user password |
| `ADMIN_PASSWORD` | Admin user password |
| `AMP_IMAGE_OWNER_ID` | Project ID owning the amphora image |
| `AMP_SECGROUP_LIST` | Security group ID for amphora instances |
| `AMP_FLAVOR_ID` | Flavor ID for amphora instances |
| `AMP_BOOT_NETWORK_LIST` | Network ID for amphora management network |

## Running

```sh
podman kube play octavia.yaml
```

This starts a Pod with five containers sharing host networking:

| Container | Command |
|---|---|
| `api` | `uwsgi --ini /etc/octavia/octavia-uwsgi.ini` |
| `worker` | `octavia-worker` |
| `health-manager` | `octavia-health-manager` |
| `housekeeping` | `octavia-housekeeping` |
| `driver-agent` | `octavia-driver-agent` |

## Development

Packages are installed in editable mode. The Pod mounts the local source trees into each container, so edits on the host take effect immediately without rebuilding:

```sh
podman kube play octavia.yaml
# edit ./octavia or ./ovn-octavia-provider — changes are live inside the containers
```

To stop the Pod:

```sh
podman kube down octavia.yaml
```
